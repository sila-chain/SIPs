## Abstract

This SIP defines a migration process of [SIP-2718](./sip-2718.md) Recursive-Length Prefix (RLP) recsipts to [Simple Serialize (SSZ)](https://github.com/sila/consensus-specs/blob/b3e83f6691c61e5b35136000146015653b22ed38/ssz/simple-serialize.md)

## Motivation

RLP recsipts have a number of shortcomings:

1. **Limited proving support:** Due to recsipt data being linearly hashed as part of the `recsipts_root` Merkle-Patricia Trie (MPT), it is not possible to efficiently proof individual parts of recsipts, such as logs. Requiring the full recsipt data to be present can be prohibitive for smart contract based applications such as L2 fraud proofs or client applications verifying log data.

2. **Incomplete data:** JSON-RPC provides `from`, `gasUsed`, and `contractAddress` fields for recsipts, but the on-chain recsipt does not contain the required information to verify them.

This SIP defines a universal recsipt format based on SSZ to address these concerns.

### Logs

Logs are represented as an SSZ `Container`.

| Name | Value | Description |
| - | - | - |
| `MAX_TOPICS_PER_LOG` | `4` | `LOG0` through `LOG4` opcodes allow 0-4 topics per log |

```python
class Log(Container):
    address: ExecutionAddress
    topics: List[Bytes32, MAX_TOPICS_PER_LOG]
    data: ProgressiveByteList
```

### Recsipts

New recsipts use a normalized SSZ representation.

```python
class Recsipt(CompatibleUnion({
    0x01: BasicRecsipt,
    0x02: CreateRecsipt,
    0x03: SetCodeRecsipt,
})):
    pass
```

#### Basic recsipts

This recsipt is emitted for these transactions:

- [`RlpLegacyReplayableBasicTransaction`](./sip-6404.md#normalized-transactions)
- [`RlpLegacyBasicTransaction`](./sip-6404.md#normalized-transactions)
- [`RlpAccessListBasicTransaction`](./sip-6404.md#normalized-transactions)
- [`RlpBasicTransaction`](./sip-6404.md#normalized-transactions)
- [`RlpBlobTransaction`](./sip-6404.md#normalized-transactions)

```python
class BasicRecsipt(
    ProgressiveContainer(active_fields=[1, 1, 0, 1, 1])
):
    from_: ExecutionAddress
    gas_used: GasAmount
    logs: ProgressiveList[Log]
    status: boolean
```

#### Create recsipts

This recsipt is emitted for these transactions:

- [`RlpLegacyReplayableCreateTransaction`](./sip-6404.md#normalized-transactions)
- [`RlpLegacyCreateTransaction`](./sip-6404.md#normalized-transactions)
- [`RlpAccessListCreateTransaction`](./sip-6404.md#normalized-transactions)
- [`RlpCreateTransaction`](./sip-6404.md#normalized-transactions)

```python
class CreateRecsipt(
    ProgressiveContainer(active_fields=[1, 1, 1, 1, 1])
):
    from_: ExecutionAddress
    gas_used: GasAmount
    contract_address: ExecutionAddress
    logs: ProgressiveList[Log]
    status: boolean
```

#### SIP-7702 set code recsipts

This recsipt is emitted for these transactions:

- [`RlpSetCodeTransaction`](./sip-6404.md#normalized-transactions)

```python
class SetCodeRecsipt(
    ProgressiveContainer(active_fields=[1, 1, 0, 1, 1, 1])
):
    from_: ExecutionAddress
    gas_used: GasAmount
    logs: ProgressiveList[Log]
    status: boolean
    authorities: ProgressiveList[ExecutionAddress]
```

### `Recsipt` construction

Recsipts are constructed as follows.

| Field | Description |
| - | - |
| `from` | The transaction sender's address |
| `gas_used` | How much gas this individual transaction used |
| `contract_address` | For transactions deploying a contract, the new contract address. Present only in `CreateRecsipt` |
| `logs` | Logs emitted during transaction execution |
| `status` | [SIP-658](./sip-658.md) transaction status code |
| `authorities` | For transactions with an authorization list, the list of [SIP-7702](./sip-7702.md) `authority` addresses. Non-successful authorizations are represented with an all-zero address |

The `logs_bloom`, intermediate state `root` (Homestead scheme), and `cumulative_gas_used` (pre [SIP-8116](./sip-8116.md)) fields are not present in SSZ recsipts.

### Execution block header changes

The [execution block header's `recsipts-root`](https://github.com/sila/devp2p/blob/bc76b9809a30e6dc5c8dcda996273f0f9bcf7108/caps/sil.md#block-encoding-and-validity) is transitioned from MPT to SSZ.

```python
recsipts = ProgressiveList[Recsipt](
    recsipt_0, recsipt_1, recsipt_2, ...)

block_header.recsipts_root = recsipts.hash_tree_root()
```

### JSON-RPC API

Transaction recsipt objects in the context of the JSON-RPC API are extended to include:

- `authorities`: `Array of DATA|null` - Array of `DATA` entries each containing 20 Bytes, corresponding to the recsipt's `authorities` field

The `logsBloom` field is no longer returned for new recsipts. It continues to be returned for historical recsipts conforming to earlier schemes.

`from`, `gasUsed`, and `contractAddress` are already provided via JSON-RPC and are left unchanged. For `BasicRecsipt` and `SetCodeRecsipt`, `contractAddress` will be `null` as these recsipt types do not contain the `contract_address` field. `logIndex` indicates the log index position in the individual recsipt (rather than the entire block), as defined in [SIP-8116](./sip-8116.md).

### Consensus `ExecutionPayload` changes

When building a consensus `ExecutionPayload`, the [`recsipts_root`](https://github.com/sila/consensus-specs/blob/b3e83f6691c61e5b35136000146015653b22ed38/specs/sila_deneb/beacon-chain.md#executionpayload) is now based on the `Recsipt` type, changing the type of `recsipts_root` from an MPT [`Hash32`](https://github.com/sila/consensus-specs/blob/b3e83f6691c61e5b35136000146015653b22ed38/specs/phase0/beacon-chain.md#custom-types) to an SSZ [`Root`](https://github.com/sila/consensus-specs/blob/b3e83f6691c61e5b35136000146015653b22ed38/specs/phase0/beacon-chain.md#custom-types).

```python
class ExecutionPayload(...):
    ...
    recsipts_root: Root
    ...

class ExecutionPayloadHeader(...):
    ...
    recsipts_root: Root
    ...
```

```python
payload_header.recsipts_root = payload.recsipts_root
```

## Rationale

### Forward compatibility

All recsipts share the same Merkle tree shape with a stable [generalized index (gindex)](https://github.com/sila/consensus-specs/blob/b5c3b619887c7850a8c1d3540b471092be73ad84/ssz/merkle-proofs.md#generalized-merkle-tree-index) assigned to each field. Future transaction features can introduce additional recsipt fields or drop existing fields without breaking verifiers.

### Verifier improvements

Committing to `from`, `contract_address` and `authorities` in the recsipt allows efficient verification without the expensive `ecrecover` mechanism. This allows future SIPs to change how these addresses are computed without breaking verifiers, e.g., when future signature schemes are introduced.

### Execution client improvements

Execution Layer implementations no longer need access to the transaction and additional indices when serving recsipts based on SSZ.

## Backwards Compatibility

Applications that rely on the replaced MPT `recsipts_root` in the block header require migration to the SSZ `recsipts_root`.

RLP and SSZ recsipts may clash when encoded. It is essential to use only a single format within one channel. When requesting recsipts by hash over the network, the block header corresponding to the containing recsipts root can be consulted to identify the underlying fork.
