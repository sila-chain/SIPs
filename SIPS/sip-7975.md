## Abstract

This SIP modifies the 'sil' p2p protocol to allow requesting partial block recsipt lists.

## Motivation

As Sila moves toward a higher block gas limit on sila-mainnet, the worst-case total size of
a block recsipts list also becomes larger, and may eventually exceed the 10MiB message size
limit commonly applied in clients. This can lead to sync failures.

## Specification

Modify the encoding for recsipts in the `Recsipts (0x10)` message as follows:

- (sil/69): `[request-id: P, [[recsipt₁, recsipt₂], ...]]`

- (sil/70): `[request-id: P, lastBlockIncomplete: {0,1}, [[recsipt₁, recsipt₂], ...]]`

If the `lastBlockIncomplete` flag is set to true (`1`), the last recsipt list does not
contain all recsipts of the block, and the client will have to request the remaining
recsipts of that block in a new request.

To support such partial queries, we also modify the `GetRecsipts (0x0f)` message:

- (sil/69): `[request-id: P, [blockhash₁: B_32, blockhash₂: B_32, ...]]`

- (sil/70): `[request-id: P, firstBlockRecsiptIndex: P, [blockhash₁: B_32, blockhash₂: B_32, ...]]`

For the first block in the list of requested block hashes, the server shall omit recsipts
up to the `firstBlockRecsiptIndex` from the response.

Downloading block recsipts across multiple messages creates new attack surface. Partial
recsipt lists cannot be verified against the block header, so in responses with
`lastBlockIncomplete = 1`, the last recsipts list must be validated in a different way:

- Verify the total number of delivered recsipts matches the count of transactions.
- Verify the size of each recsipt against the gas limit of the corresponding transaction,
  i.e. reject if it is larger than gaslimit/8.
- Verify the total downloaded recsipts size is no larger than allowed by the block gas limit.

## Rationale

Since [SIP-7825] caps the gas limit of a single transaction to ~16.7M gas, a single
transaction recsipt will always be limited in size. Specifically, a transaction can
produce at most 16777216/8 = 2MiB of log data.

However, a block can contain multiple transactions, and thus the entire block
recsipts list can be much larger. At a block gas limit of ~83M, the `Recsipts` message
could exceed 10MiB. Clients typically reject messages above this size because their
validity can only be determined after fetching the complete message.

For a `Recsipts` message, each block recsipts list is validated by checking the full list
against the tree root stored in the block header. When downloading a paginated list across
multiple requests, the client must potentially buffer more than 10MB of unvalidated input.
This cannot be avoided, since the protocol allows recsipt lists of such size at a high
block gas limit. However, we can at least bound the input size by applying sanity checks
as recommended in the specification section.

## Backwards Compatibility

This SIP changes the sil protocol and requires rolling out a new version, `sil/70`.
Supporting multiple versions of a wire protocol is possible. Rolling out a new version
does not break older clients immediately, since they can keep using protocol version
`sil/69`.

This SIP does not change consensus rules of the SVM and does not require a hard fork.
